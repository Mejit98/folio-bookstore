# Правила работы с репозиторием

## Ветки

| Ветка | Назначение |
|-------|------------|
| `main` | стабильная версия; в неё попадает только завершённый спринт, на нём ставится метка `sprint-N` |
| `develop` | интеграционная ветка текущего спринта |
| `feature/<спринт>-<кратко>` | работа над задачей, например `feature/sprint-1-ui-prototype` |
| `fix/<кратко>` | исправление ошибок |

Слияние `feature/*` в `develop` выполняется через pull request с проверкой вторым участником команды.

## Коммиты

Формат: `<тип>(<область>): <описание в повелительном наклонении>`.

Типы: `feat` — новая функциональность, `fix` — исправление, `docs` — документация,
`style` — оформление без изменения логики, `refactor`, `test`, `chore` — служебные изменения.

Примеры: `feat(ui): add catalog page`, `chore(server): scaffold express app`.

## Стандарт оформления кода

- Отступ — 2 пробела, кодировка UTF-8, перенос строк LF (см. `.editorconfig`).
- Переменные и функции — `camelCase`; классы и компоненты Vue — `PascalCase`; константы — `UPPER_SNAKE_CASE`.
- Файлы компонентов Vue — `PascalCase.vue`; файлы серверных модулей — `camelCase.js`.
- Строки — в одинарных кавычках, точка с запятой в конце оператора.
- Комментарии пишутся на русском языке, без сокращений; поясняют причину решения, а не повторяют код.
- Секреты и параметры подключения хранятся только в `.env`; в репозиторий попадает `.env.example`.

## Стандарт интерфейса

Цвета, шрифты и компоненты описаны в [ui-style-guide.md](ui-style-guide.md).
Интерфейс русскоязычный; сообщения об ошибках — понятные пользователю, без технических терминов.

## Определение «Сделано» (Definition of Done)

1. Код находится в Git, ветка слита через pull request.
2. Результат проверен вручную по критериям из технического задания.
3. Данные проверяются и на клиенте, и на сервере.
4. Изменения описаны в документации или README.
5. Карточка в Trello перенесена в колонку «Готово».
